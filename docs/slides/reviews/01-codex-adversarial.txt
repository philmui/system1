  Audience and preview documents load the persisted auto-advance settings and run this timer independently. After reloading with auto-advance enabled, they can advance without a presenter command. - [high] Synchronize teaching interactions across presentation windows (src/interactions.js:10-14)
  Trace advancement, threshold changes, cost changes, and answer reveals mutate only the current document. Presenter previews and the audience window load independent copies; the transport synchronizes slide indexes and annotations but carries no interaction state. A demonstration changed in the preview therefore leaves the projected lesson unchanged, and reopening the audience resets its examples.
  Recommendation: Give interactions serializable state owned by the presenter, broadcast changes to audience/previews, and restore that state when an audience window reconnects.

  The delayed callback reads renderedNoteId and the editor value after 300 ms. Navigating during that interval replaces both with the next slide's values, so the previous edit is never saved despite the Saved indicator. A focused execution reproduced saving slide B's original text while losing slide A's edit.
  Recommendation: Capture the slide ID and text when scheduling the save, and flush pending edits before navigation or exit.

  The key handler exempts inputs and textareas but not buttons. With slide 16's Next event button focused, pressing Space calls go() for slide 17, hiding and making the original button inert before its normal activation.   Recommendation: Skip slide-navigation shortcuts when focus is within an interactive control, including buttons and links; preserve their native Enter and Space behavior.
