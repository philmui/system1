September 29, 2026. Implements the [education brief](../notes/09-disaggregated-intelligence-app-plan.md). This record separates executed software checks from browser and human validation that the environment did not permit.

## Structure and implementation checklist

It still opened on operational workspaces, and classification publication waited for the batch. The baseline suites passed 81 backend tests and 41 frontend unit tests. The default lesson is a checked-in catalogue generated by actual fixture workflows in a temporary store. Opening it needs no upload, provider key, or new operational run. `/api/lessons` serves the same catalogue. Experiment requires the backend policy endpoint; its original recording remains readable if that service is unavailable.

Explore contains Classify documents, Find & compare, and Review & redact. `/#workflow` remains an alias for the legal-review scene. Existing `/#library`, `/#discover`, and `/#runs/<id>` links remain valid. New learning URLs retain the selected scene, example, recording, document, and comparison source. Run inspection supplies a return to the lesson. A transition to a different prepared workload is labeled explicitly.

## What the examples establish

- The five-document classification catalogue executes five bounded calls and two frontier interpretation calls. Its exception-heavy mix is a teaching set, not an estimate of production prevalence.
- The proposed and finalized agreements retain a controlled `contract · 96%` signal. Their actual text changes the guard result. Ordinary uploads and live providers never inherit that fixed confidence.
- The default virtual workload has 100 readable documents and 20 exceptions. The disaggregated strategy makes 100 bounded and 20 frontier calls; the stated one-call baseline makes 100 frontier calls. Avoiding 80 frontier calls increases total model requests from 100 to 120 in this example.
- Virtual categories and review outcomes are held equal by assumption. Costs and service times are editable assumptions, not measured savings. Unknown prices remain unavailable. Recorded fixture durations are not model-performance measurements.
- Direct V2 publications are searchable before unrelated interpretation or review completes. A pending proposal is absent from retrieval. Acceptance, approval, publication, and batch completion remain distinct states.
- Discovery assigns frontier generation deliberately to a comparison request. Find can use code retrieval without a narrative answer. Bounded support screening remains fallible; exact citation validation enforces its narrower implemented contract.

The [publication design](independent-publication.md) defines commit identities, cancellation, retained approved versions, replay compatibility, and failure behavior. Catalogue version `disaggregated-lessons-v2` and teaching pack `classification-teaching-v2` preserve earlier recordings rather than editing their events. No cleanup runs when a lesson opens, and no live provider calls or operational database mutations were needed for this redesign.

The later [v3 mixed-purpose report update](mixed-purpose-report-v3.md) retains the exact v2 catalogue and the original plain progress source. The new entry example demonstrates the unchanged text guard even with a confident report judgment; it no longer presents prepared uncertainty as a promised live outcome.

## Independent adversarial review

An independent Codex agent reviewed the actual implementation for misleading evidence, navigation surprises, publication races, unfair comparison, replay leakage, and first-time comprehension. Its work included source review and independently executed focused tests; it did not inspect rendered browser screenshots.

| Finding | Correction |
| --- | --- |
| A code-only Find plan could be counted as a frontier request. | Count the actual recorded intent route; verify Find = 0 and Compare = 2. |
| Selecting a virtual comparison document could replace the retained document context. | Keep virtual selection local; return using the selected recorded document ID. |
| Original judgment could overshadow the proposal and final category. | Show the proposal only after its event and the published category only after its commit. |
| Exclusion and early pending-review states were unclear. | Name an excluded outcome and represent awaiting review at the worker state, before the shared review panel. |
| Play was below a tall mobile graph; duplicated headings added clutter. | Put the primary action above the graph and retain one visible page heading. |
| Discovery captions retained desktop coordinates in portrait mode. | Remove column captions in the vertical journey; test bounds including every annotation. |
| Wide comparison lanes could not be seen together. | Add a compact, side-by-side desktop layout and verify routes avoid unrelated nodes. |
| Source inspection did not pause playback. | Opening a drawer pauses without resetting progress. |
| Safeguard and Discovery links silently changed the corpus; a variant replay returned to the original wording. | Label the new workload explicitly and replay the selected variant under recorded policy. |
| Clicking the already-selected example did not replay it. | Every example-card selection starts a fresh replay from its decision. |
| V2 batch reconciliation could animate a second publication transfer. | Animate the per-document commit route in V2; retain the batch-index route only for historical workflows. |

The reviewer independently passed 30 focused frontend tests, 20 backend education/publication tests, and subsequently all 10 execution-layout tests. After the corrections, the review reported no remaining source-based blocker in publication consistency, comparison fairness, experiment isolation, or replay-prefix evidence. This is source and automated behavior evidence, not a usability certification.
